# ACCESS TIERS

## Access Architecture

This ecosystem is organized around governed access tiers.

Not everyone receives the same level of:

- visibility
- implementation detail
- archive access
- room access
- licensing rights
- operational support
- strategic interpretation

Access scales with trust, alignment, and payment.

## Tier 0 - Public Signal

Purpose:

Public trust-building and visibility.

Includes:

- public writing
- lightweight open-source contributions
- screenshots
- essays
- selected demos
- educational fragments
- founder dispatches

Does not include:

- core IP
- private architecture
- implementation detail
- commercial rights
- archive access

## Tier 1 - Supporter

Purpose:

Community support and low-friction participation.

Includes:

- support access
- updates
- selected downloads
- occasional previews
- supporter recognition

Typical mechanism:

- Stripe support
- subscriptions
- sponsorships

## Tier 2 - Product Buyer

Purpose:

Access to bounded assets.

Includes:

- downloadable kits
- templates
- guides
- governance packs
- starter systems

Does not include:

- implementation rights
- resale rights
- white-label rights

## Tier 3 - Room Participant

Purpose:

Entry into a governed room or structured workflow.

Includes:

- guided access
- workflow systems
- private demos
- limited archive visibility
- implementation context

Rules:

- occupancy limits
- access windows
- export boundaries
- no redistribution

## Tier 4 - Operator / Advisory

Purpose:

Strategic implementation and high-value support.

Includes:

- architecture guidance
- implementation planning
- governance hardening
- workflow design
- strategic interpretation
- systems adaptation

Typical formats:

- intensives
- retainers
- sprint engagements
- consulting rooms

## Tier 5 - Enterprise / License

Purpose:

Institutional deployment or commercial rights.

Includes:

- commercial licenses
- custom deployment
- institutional onboarding
- team access
- enterprise support
- governance review

Requires:

- written agreement
- defined scope
- payment terms
- licensing boundaries
- operational review

## Upgrade Logic

Movement between tiers should feel natural and inevitable.

The sequence:

1. public trust
2. emotional resonance
3. useful artifact
4. room access
5. strategic dependency
6. institutional integration

## Core Principle

The system should make people feel:

> "Of course this costs money."

because the value, structure, access, and transformation are obvious.
