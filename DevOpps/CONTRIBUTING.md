# Contributing to DevOpps

## Scope

DevOpps is operated as a domain pack and execution system for opportunity-to-income conversion.
Contributions should strengthen one of the following:

- Intake reliability
- Scoring quality
- Deployment conversion
- Artifact quality and governance

## Contribution Rules

1. Keep changes file-native and auditable.
2. Preserve provenance metadata and timestamps.
3. Prefer additive changes to ontology/config over hard-coded logic.
4. Update docs whenever process behavior changes.

## Pull Request Checklist

- [ ] Updated `domains/devopps` configs if scoring or intake changed
- [ ] Updated docs under `docs/` if process changed
- [ ] Regenerated exports if digest format changed
- [ ] Added notes for revenue or deployment implications
