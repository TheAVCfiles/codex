# Dutchess Research Continuation Kit

This note answers: **"what tools do you need to continue this"** and provides a
portable sheet/PDF-ready structure you can keep outside chat.

## Minimum tools needed to keep this moving

1. **Source capture + archiving**
   - Web capture tool (or browser export to PDF)
   - Wayback/archival snapshots for public pages that change frequently
   - Foldered evidence storage with stable filenames
2. **Structured timeline tracking**
   - Spreadsheet app (Excel/Sheets/LibreOffice) for year-indexed records
   - One row per event/action/site/program/funder item
3. **Entity graphing (optional but high value)**
   - Graph tool (Obsidian Canvas, Kumu, Gephi, or Mermaid in Markdown)
   - Nodes: orgs, sites, people, funders, grants, oversight agencies
4. **Document extraction**
   - OCR-capable PDF reader for scans
   - CSV export from tables where possible
5. **Verification lane**
   - Public filings lane (990s, county contracts, audits, TAGGS action history)
   - Program operations lane (org annual reports, site pages, licensing records)

## Immediate data lanes to continue

- IRS 990 history (2008–2025)
- Dutchess county contracts and budget lines
- CoC rosters/PIT-HIC history
- Board roster changes by year
- Site-level address map (main + satellite settings)
- Federal action-level grant modifications (including negative/zero-dollar rows)

## Portable sheet (fields)

Use these columns for each record:

- `year`
- `event_date`
- `organization`
- `program_or_award`
- `service_lane`
- `site_address`
- `city`
- `oversight_level` (county/state/federal)
- `funding_source_or_agency`
- `amount_usd`
- `action_type` (award/amendment/reversal/admin/ops)
- `source_type` (gov directory/audit/org report/etc.)
- `verification_status` (verified/partial/needs-verify)
- `notes`

## Evidence discipline

- Keep first-person narrative separate from institutional records.
- Preserve contradictory records as separate rows (do not collapse early).
- Keep all zero-dollar and negative-action grant entries; they are lifecycle
  signals, not noise.

## Export guidance

- Save working file as CSV for portability.
- Export a PDF snapshot after each major update so there is a timestamped,
  immutable checkpoint.
