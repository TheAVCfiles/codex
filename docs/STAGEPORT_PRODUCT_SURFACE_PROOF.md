The public changelog is positioned as an audit-grade trust surface, not a blog.

Observed release language includes:

- versioned public history
- shipped items
- security posture

## Proof and Verification Surface

Observed proof language includes:

- verify a single receipt
- import ledger NDJSON
- verify a ledger
- published issuer key
- issuer fingerprint
- offline verification posture
- OpenSSL verification example
- public issuer key cross-check

Core principle:

> Verification should not depend on the continued availability of the StagePort server, StagePort account, or StagePort company.

## Offline Verification Thesis

The system states that verification requires only:

- receipt JSON
- public issuer key
- verification algorithm/library

This supports the product thesis that if the company ceases to exist, a domain is rerouted, or an account is unavailable, the proof can still be independently evaluated.
