# Studio to Enterprise Pipeline

This repository is part of the personal AVC source layer. It is the studio floor, not the enterprise stage.

## Purpose

Personal repositories preserve origin, iteration, authorship, runoff, rehearsal memory, and early technical experiments. Enterprise repositories should receive promoted, cleaned, licensed, and governed assets only after the source layer has established provenance.

## Pipeline

1. Studio capture
   - Chats, Codex dumps, notes, phrase ledgers, prototypes, screenshots, and rough scaffolds.

2. Source cleanup
   - Assign path, timestamp, classification, visibility, licensing boundary, commercial pathway, and provenance note.

3. Governed promotion
   - Promote only assets that pass integrity, licensing, and operator-readiness checks.

4. Enterprise transfer
   - Move cleaned artifacts into enterprise GitHub only after the personal source record is clear.

5. Stage deployment
   - Deploy public or paid rooms only when billing, licensing, support, and visibility boundaries are explicit.

## Do not

- Do not dump raw runoff directly into enterprise repositories.
- Do not deploy every branch to Vercel by default.
- Do not publish assets without license scope.
- Do not treat public GitHub visibility as commercial permission.

## Operating law

Studio first. Enterprise second. Stage last.
